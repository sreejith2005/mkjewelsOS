# Recording capture and ingestion

Approved approach: owner approval in chat on 2026-11-04. Extend JewelOS's web UI and single Android WebView. A narrow Kotlin AudioRecord foreground service owns native capture and encrypted recovery; Supabase owns canonical sessions and authorization; a separate verified ingestion/worker service owns audio transport and optional GPU processing. This is an additive pilot, disabled until configured. No legacy auth, tables, dashboard or customer imports.

## Contracts

- Module/page `sales_recording`, route `/sales-recording`; permissions `recording.capture`, `recording.review`, `recording.coach`. Capture defaults to no role; review/coach require manager authority AND permission. The pilot is disabled by default in server configuration. Owner must explicitly enable selected users/branches.
- PCM: mono signed 16-bit little endian, 16000 Hz. Canonical chunks contain non-overlapping samples; transcription workers may prepend context, but do not persist that context as new audio. Chunk size 2 seconds (64000 bytes), final partial chunk permitted (even nonzero byte count). Sequence starts at 0. SHA-256 lowercase hex covers raw bytes. Max session 4 hours, max local queue 64 MiB; reaching either limit pauses with Needs attention, never evicts unacknowledged audio.
- `recorder-session` Edge Function authenticated by JewelOS bearer JWT: POST JSON `{action:'start',device_id,request_id,consent_version:'pilot-v1',consent:true}` or `{action:'ticket',session_id,device_id}`. Returns `{session: RecordingSession,ticket,expires_at,upload_url,stream_url}`. Ticket opaque, single-use, 60 seconds; hash only persisted. Ticket refresh always targets the same session. Server derives identity/tenant/branch from active profile and checks consent and permission. Idempotent start request; one active session per device. No customer required.
- RecordingSession JSON fields: `id,tenant_id,branch_id,employee_id,device_id,status,next_sequence,created_at,error_reason`; status `recording|paused|saving|processing|ready|needs_attention`. UUID strings. Additional fields allowed. `recorder_control_session(p_session_id uuid,p_action text,p_last_sequence integer default null)` actions pause/resume/stop. Stop seals capture intent, sets saving; ingestion commit transitions to processing only after contiguous chunks 0..last_sequence exist. Empty stream uses last_sequence=-1. Repeated stop/commit is idempotent; mismatched commit fails.
- `recorder_session_snapshot(p_session_id)` returns `{session,segments,alerts}`. `recorder_list_sessions()` returns owned sessions (or authorized manager scope). `recorder_link_customer(p_session_id,p_customer_ref)` stores only a server-verified CRM reference via existing bridge contracts if available; otherwise explicitly blocked. Never trust a free-text customer ID as verified.
- HTTPS ingestion `/v1/connect`: POST `{ticket}`; calls `recorder-ingest` Edge Function using dedicated backend-only `x-recorder-secret`, `{action:'redeem',ticket}`. Returns scoped claims from atomic ticket redemption, then ingestion issues random in-memory 5-minute lease `{ingest_token,expires_at,session,next_sequence}`; bearer token never URL. Lease expires and requires a fresh ticket for the same session. Bind lease to all five IDs. Fail closed if backend boundary unreachable. WebSocket `/v1/stream` first text frame `{type:'auth',ticket}` within 5 seconds; no binary consumed before auth. Respond `{type:'authenticated',...lease}`.
- HTTPS `/v1/chunks`: bearer lease, POST `{session_id,device_id,tenant_id,branch_id,employee_id,sequence,sha256,data}` where data is base64. WSS chunk frames same JSON plus `type:'chunk'`. ACK `{type:'ack',sequence,sha256,next_sequence}` only after private object and canonical Supabase metadata durably written. Retry same key/hash returns same ack; different hash conflicts. Accept only next sequence or an identical prior chunk. No process-local substitute for canonical deduplication.
- HTTPS `/v1/commit` and WSS `{type:'commit',last_sequence}`: lease scope, flush and ACK every byte first. End commit idempotently enqueues durable processing. `/healthz` exposes non-sensitive liveness; readiness checks dependency/queue capacity, no credentials/audio/transcript logs.
- `recorder-ingest` internal actions `redeem`, `chunk`, `commit`, `event`, `claim_job`, `finish_job`, `health`, `reconcile`. All server-only behind dedicated secret; calls only narrow recorder RPCs, never arbitrary tables. `chunk` receives claims plus sequence/hash/byte_count/object_key; `commit` claims plus last_sequence. Worker claims bounded durable leased jobs; retries/backoff/dead-letter; processing status/errors explicit. Define exact SQL/RPC adapter mapping in implementation.
- Transcript events `{segment_id,sequence,revision,text,is_final,started_ms,ended_ms}` upsert by stable segment ID and increasing revision. Final replaces provisional. Authenticated snapshot polling initially (1 second active, throttled; no anonymous feed), permission/branch filters applied server-side. Optional coaching alerts only from final unambiguous evidence and explicit manager/coach permission, opt-in, rate limit, deduplication. No text in health/logs.

## Native bridge

Keep namespace `jewelos-shell/1` and existing origin checks/navigation. Page-to-native kinds `recorder.start` with `{requestId,session,ticket,expires_at,upload_url,stream_url}`, `recorder.pause|recorder.resume|recorder.stop|recorder.status` with `{requestId,sessionId}`. Start only while activity visible and after mic/notification permission. Native-to-page DOM event `jewelos-recorder` detail `{kind:'recorder.status'|'recorder.error',requestId,sessionId,state,sequence?,queuedBytes?,level?,elapsedMs?,error?}`; fixed error codes only. Credentials never included in status/events. Repeated start for same session refreshes ticket, never resets queue. Page JWT never leaves WebView. Native session + encrypted chunk manifest survives process death; ingest lease/ticket held only in memory. On relaunch emit interrupted/needs_attention and await deliberate resume/ticket; no auto mic restart.

## UI and lifecycle

Clear consent and browser permission action, red visible recording state, timer/meter, pause/resume/stop, network/recovery state. Web secure context and AudioWorklet PCM capture with IndexedDB AES-GCM bounded queue; key stored as non-extractable CryptoKey. Browser closure/background limitations stated. Native uses service notification stop action and interruption callbacks, encrypted Android Keystore files, ordered retries to same session. Pause flushes partial chunk, stops microphone, retains open session; resume requires explicit action. Stop stops mic, flushes, Saving -> Processing -> Ready/Needs attention. Failures retain audio and durable session. Crash reconciliation marks stale active sessions needs_attention without inventing completion or online status.

## Storage, validation and release

Private object store, exact scope-derived paths, server-side encryption and restricted IAM; configurable retention (pilot default seven days), authenticated signed playback only if authorized. Canonical metadata stays JewelOS Supabase, customer master stays separate CRM. No broad AWS Supabase service-role credential. Tests cover authorization, expiry/replay, chunk disconnect/ack loss/restart/partial flush/order/conflicts/gaps, job failure and final reconciliation. Native physical tests: denial, visible start, lock, Home, call, route/reload, battery saver, offline/recovery, kill/relaunch, notification Stop, queue full. Pilot measures end-of-audio -> first provisional event p50/p95 with warm/cold model, concurrent sessions and reconnects; latency is unmeasured until then.

Native release only scripts/release-mobile.ps1 after local, staging, physical-device and production gates. No public APK or production activation if gates cannot be proven.
