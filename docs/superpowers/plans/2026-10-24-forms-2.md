# Forms 2.0 Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task by task.

**Goal:** Extend the existing Forms engine with immutable provenance, saved checkpoints, a live preview and a reviewed AI HTML importer.

**Architecture:** Keep existing audited mutations and pinned template identities. Record checkpoints transactionally after definition mutations. Shared deterministic logic validates AI proposals and describes definition changes. The existing renderer serves preview and history; the existing builder edits imported drafts.

**Tech stack:** React, strict TypeScript, Supabase Postgres/Edge Functions, Vitest, pgTAP.

**Spec:** User attachment `Pasted text.txt`, Forms 2.0 Parts 1–10 (2026-10-24).

## Global constraints

- No production deployments, migration applies, or production data changes.
- Preserve existing submissions, assignment identities, FMS pinned versions and library access.
- Imported scripts are inert text. No URLs or source handlers execute.
- Provider calls are authenticated, tenant scoped, quota limited and server side.
- AI proposals save only after review, as drafts; publication is separate.
- History contains definitions, never submission answers. Restoration creates a new draft and refuses an existing draft conflict.

## Review focus

- In-place published edits must produce checkpoints without changing template IDs.
- Concurrent/stale saves must fail safely; no-op saves must not add checkpoints.
- FMS creation provenance must be verified by the server and survive workflow deletion.
- Unsupported or ambiguous imported conditions must block unreviewed conversion.
- Preview must preserve compatible answers and cannot upload or submit data.

## Tasks

1. Data contracts: inspect latest mutations and tests; add append-only checkpoint/provenance storage, authorized reads/restoration, optimistic save wrappers and AI quota RPCs. Add pgTAP allowed/denied/conflict/immutability cases. Update generated types.
2. Shared logic: test then implement deterministic definition diffs and strict versioned source/conversion contracts; static extraction, sensitive-content rejection and deterministic validation. Exercise nested rules and unsupported integrations.
3. Live preview: test then extend shared builder/renderer with persistent responsive split panes, accessible resize, selection synchronization, reset and compatible-answer reconciliation. Preserve outline/routes/editing/save behavior.
4. Provenance/history UI: wire FMS source context into atomic creation; library origin/usage filters, history timeline, exact checkpoint preview/compare, restore and copy actions. Add focused integration tests.
5. AI importer: inert highlighted source editor, multiple file inputs, real analysis/review states, report/source references, focused refinement, native builder handoff and explicit draft save. Add separate caller-authenticated Forms endpoint using existing provider conventions.
6. Integration: update Kiara help and administrator instructions. Run focused tests, pgTAP where local runtime is available, lint/typecheck/build and phone/desktop rendered checks. Review final diff; report exact evidence and remaining gates.
