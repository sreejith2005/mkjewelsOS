## C. Implemented in this change

### C1. Per-workflow FMS access (migration 0390)

Builders (`fms.manage`) give one person **View only**, **Edit** or **Edit and
publish** on one workflow (every version) from the workflow card: **⋯ ›
Access**.

- Table `fms_flow_access_grants` (one live grant per person and workflow,
  revoked rows kept as history, RLS on, no browser grants).
- `fms_my_flow_access`, `can_edit_fms_flow`, `can_publish_fms_flow`. A grant
  counts only while the person's account is active and they hold `fms.view`.
- Draft save, new version and start-trigger test accept Edit; publish, pause /
  resume and live start-trigger change accept Publish; archive, delete,
  restore, erase and module context stay `fms.manage` only. Creating a new
  workflow still needs `fms.manage`.
- `fms_definition_write_guard` (0387) also accepts an Edit/Publish grant.
- Read policies for granted readers on `fms_flows`, `fms_stage_assignees`,
  `fms_branch_rules` (`fms_stages` follows flows).
- RPCs `list_fms_flow_access`, `grant_fms_flow_access_with_audit`,
  `revoke_fms_flow_access_with_audit`, `list_my_fms_flow_access`; audit
  actions `fms_flow_access_granted` / `fms_flow_access_revoked`. With
  isolation On only people in the granter's scope can be named.
- Web: card buttons follow the grant (**View workflow**, **Edit draft**, **New
  version**, Pause/Resume); builder `readOnly` mode (badge **View only**; no
  Save draft, Publish, Add Step, Undo/Redo, Import / Export, AI; every change
  refused in `commit`/`persist`), `canPublish` hides Publish for Edit.
- Running work is unchanged: completing an assigned step never depends on a
  definition grant.

### C2. CRM client archive / restore (CRM 20261107000200)

- `clients.archived_at / archived_by / archive_reason`; `archive_client`
  (reason required) and `restore_client`, CRM Super Admin only, audited in
  `crm_private.audit_logs`.
- Archived clients leave the Client Database list (`browse_crm_records`,
  `browse_crm_records_page`); filter **Archived › Archived clients only**
  lists them. Phone search, lookups and walk-ins still find them, so a
  returning customer is never registered twice, and their walk-in still saves.
- Archive columns change only through the functions (trigger
  `clients_aa_archive_guard`). **`DELETE` on `clients` revoked from
  browsers** - nothing is ever hard-deleted from the API.
- Profile banner **This client is archived** with **Restore client**;
  **Archive client** button for Super Admin.

### C3. Users question filters (migration 0391)

- Setting `validation.userFilter` on a Users question: rules on Department,
  Designation, Store / branch, Franchise, Role (Is equal to / Is not equal to /
  Is in / Is not in / Is empty / Is not empty) or Name (Contains / Does not
  contain), matched All (AND) or Any (OR). Example: Salesperson = Department
  Is equal to Sales.
- Server: `normalize_form_user_filter` (allowlisted fields/operators,
  identifier values, max 10 rules x 50 values; no free column names or SQL),
  `form_user_matches_filter`, `assert_form_user_filter` called in
  `submit_form_base_with_audit` and `fms_validate_candidate_form` after the
  existing active / company / location check. A crafted request naming a
  person outside the filter is refused (23514).
- The filter only narrows: the list still comes from `v_task_users` (franchise
  boundary); `v_task_users` gains `designation_id`.
- Core mirror `formUserMatchesFilter`; builder editor **Who can be chosen**.

### C4. International phone on Form Builder phone questions (web only)

- The CRM's approved phone rules moved to `packages/core/src/phone.ts`; the
  CRM file re-exports them (one implementation).
- `FormPhoneInput`: country list (India first), number box, phone keyboard,
  paste/typed `+44 ...` picks its country, per-country message (India: 10
  digits), saved as `+<code><number>`, displayed `+91 9876543210`.
- Legacy answers without `+` are never re-guessed (the CRM's `splitPhone`
  would read `9876543210` as Iran +98; `formPhoneParts` does not).
- CRM client lookup now waits for a complete number (`isCompletePhone`): with
  `+91` the old "10 digits" test would have fired after 8 typed digits.

### C5. Desktop sidebar icon rail (web only)

Closing the sidebar, or choosing a section, shrinks it to a 64px icon rail
instead of hiding it; icons are named (aria-label + hover title), open
questions show as a dot, page padding follows, `Toggle sidebar` reports
`aria-expanded`. Phones unchanged.

Every change updated `packages/core/src/assistant/appHelp.ts` and
`docs/ASK_KIARA_APP_HELP_REVIEW.md`. Kiara tool decision: no new Kiara tool
(administration/builder settings); Kiara stays read-only.
